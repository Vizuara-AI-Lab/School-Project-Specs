# School Projects – Change Specifications Repository

This repository contains **detailed change specifications** for all school-level projects (Classes 5–10).

Each project has its **own folder** with:
- A clear description of what needs to be changed
- Screenshots or reference images
- Notes, constraints, and expectations

This repository is the **single source of truth** for development changes.


## Purpose of This Repository

These projects are used by **school students** to learn concepts in:
- Machine Learning
- Artificial Intelligence

The goal of the changes described here is to:
- Improve clarity and usability for students
- Make concepts easier to understand
- Keep projects age-appropriate and engaging
- Ensure technical correctness without overengineering

## Some instructions to follow in all projects
Below is an **expanded and improved set of rules**, written in a **clear, professional, school-project style**, and suitable to be added directly to your repository README or guidelines document.

### 🧠 Educational & Pedagogical Rules

1. **Age-Appropriate Language**

   * All text must be understandable by the target class level.
   * Avoid advanced technical jargon unless it is clearly explained.
   * Use short sentences, examples, and analogies.

2. **Concept-First Approach**

   * Always explain *what* and *why* before *how*.
   * Code or models must never appear without prior conceptual explanation.
   * Each page should teach **one main idea only**.

3. **Step-by-Step Learning**

   * Concepts must be broken into small steps.
   * Each step should build on the previous one.
   * No sudden jumps in difficulty.

4. **Visual Learning Priority**

   * Prefer diagrams, grids, cards, and icons over long text.
   * Every major concept should have a visual representation.
   * Tables and grids must be used wherever data is shown.

### 🎨 UI / UX Design Rules (Mandatory)

1. **Consistent Layout System**
   * Padding on left and right must be consistent on every page.
   * Content should never touch screen edges.

2. **Progress Bar Requirement**
   * A progress bar must be visible on all learning pages.
   * It should clearly show:
     * Current step
     * Completed steps
     * Remaining steps
   * Progress must update as the student moves forward.

3. **Page Structure**
   * Each project must be divided into **multiple pages**, not one long page.
   * Recommended structure:
     1. Landing Page
     2. Concept Introduction
     3. Data Explanation
     4. Model / Logic Explanation
     5. Interactive Section
     6. Quiz
     7. Game

4. **Landing Page Design**
   * Must have a **centered card layout**.
   * Must include:
     * Company logo
     * Project title
     * Short, simple description
   * Logo and favicon are mandatory.
   * Background must be: (Project Need) or Black/White background

3. **Font**
   * Use consistent font throughout as much as possible. 
   * Headings and special sections may a distinct font.
   * Quicksand/Figtree is preferred for body text.

### 🎮 Interactivity Rules

1. **Quizzes (Mandatory)**
   * At least **one quiz after every major concept**.
   * Quiz questions must:
     * Be simple and clear
     * Reinforce learning, not trick students
   * Immediate feedback is required (correct / incorrect).

2. **Games (Mandatory)**
    * Each project must include **at least 2 games**.
    * Games must be:
      * Simple to understand
      * Related directly to the concept
    * Examples:
      * Match the data
      * Predict the outcome
      * Drag-and-drop classification
      * Pattern recognition games


### 🧪 Machine Learning & AI Rules

11. **No Overengineering**

    * Use the simplest possible logic or model.
    * Avoid unnecessary libraries or advanced math.
    * Focus on **conceptual understanding**, not performance.

12. **Explain Predictions Clearly**

    * Every prediction must explain:
      * Input
      * Process (in simple terms)
      * Output
    * Students should be able to explain the prediction in their own words.
